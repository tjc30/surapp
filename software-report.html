Architecture & System Specification

Planetary Climate Observatory

Comprehensive software report detailing component interactions, data ingestion pipelines, SurrealDB storage engine, Rust Axum backend API, and React SPA visualization layer.

1. Architecture Overview & High-Level Topology

The Planetary Climate Observatory is a multi-tier scientific dashboard built for high-performance retrieval and visualization of decadal climate datasets (Global Temperature Anomalies, Holocene & Modern Atmospheric CO₂, Canadian Megafires, Regional Drought Indices, and Multi-Indicator Flood Disasters).

Tier 1
Raw Data & Ingestion

Authoritative inputs from NOAA, EPA, CFS/CWFIS, and EM-DAT transformed via Python into normalized database records.

Tier 2
SurrealDB 3.3 Engine

Persistent on-disk storage engine (SurrealKV / RocksDB) running on port 8000 with sub-millisecond query execution.

Tier 3
Rust / Axum Gateway

Asynchronous Tokio/Axum REST API server on port 3000 handling SurrealQL serialization, stats, and SPA asset serving.

Tier 4
React 18 / Vite SPA

Dark glassmorphism user interface with Chart.js dual-axis canvases, responsive KPI grids, and CSV export tools.

2. What Each Part Does

1. Data Ingestion Scripts (Python)

Script Input Source Target Table Responsibility
load_temps.py input/NOAA world temps/aravg.mon...asc temps Parses 177 years (1850–2026) of NOAA annual land-ocean temperature anomalies and 95% uncertainty ranges.
load_co2.py input/CO2/co2-concentration-long-term.csv & co2_annmean_mlo.txt co2 Combines 10,000-year Antarctic ice cores (-10,000 BCE to modern) with continuous in-situ NOAA Mauna Loa measurements.
load_wildfires.py input/Fires/canada-wildfires.csv wildfires Ingests 27 years of Canadian CFS/CWFIS wildfire totals, converting hectares to million acres and calculating megafire shifts.
drought-plott.py input/Drought/pdsi-regional-divs.txt drought_pdsi Ingests 76 years of monthly PDSI comparing the arid West (Region 109) and humid Northeast (Region 101) with 24-month rolling means.
load_flooding.py input/Flooding/global-and-US-flooding.txt & US_flooding-cost flood_trends, flood_costs Ingests high-tide flood days (NOAA CO-OPS), heavy rain area % (EPA), global disasters (EM-DAT), and decadal billion-dollar flood damages (NOAA NCEI).
load_sources.py Institutional catalog sources Stores scientific provenance, citation links, update cadence, and institutional contacts.

2. Database Layer (SurrealDB 3.3)

SurrealDB runs as a daemon process bound to 127.0.0.1:8000. It persists data to disk in /home/timu/surapp/data using its high-speed SurrealKV/RocksDB storage engine. It provides ACID transactions, native SQL parsing, filtering, and aggregation.

3. Backend Gateway Server (Rust + Axum)

Located in backend/src/main.rs, this compiled binary serves the REST API and the frontend SPA:

  • SurrealDB Bridge: Translates incoming HTTP requests into SurrealQL, dispatches them over local HTTP to port 8000, and deserializes results into typed Rust structures.
  • Statistical Calculation Engine: Computes real-time leaderboards, baseline comparisons, and peak values.
  • Static File Delivery: Serves the compiled production bundle from frontend/dist with no-cache headers so users always see the latest code without stale browser caches.

4. Orchestration & Lifecycle Scripts

Script Purpose
start_app.sh Automated startup: ensures SurrealDB is running, checks that all tables have records (auto-running loaders if empty), compiles the frontend with Vite, launches Axum backend in background, and verifies API health.
start.sh Starts the standalone SurrealDB server process on 127.0.0.1:8000.
stop_app.sh Cleanly shuts down both the Axum backend and SurrealDB background processes.
status.sh Checks whether SurrealDB and Axum are running and displays active process IDs.
